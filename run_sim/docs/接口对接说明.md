## 0. 总览：闭环里谁调用谁

```
run_loop.py（API-3 闭环，李煜荣维护）
   ├─ 每轮生成后  → 调 lint.lint(gen_file)            # 替换你现在的 lint()
   ├─ lint fail   → 调 auto_fix.auto_fix(gen_file)     # 自动修复（本轮可暂不接）
   ├─ 仿真验证    → 调 run_full_flow.run_full_flow(...) # 替换你现在的 simulate()
   └─ 失败回喂    → 直接用返回 JSON 里的 error / lint_errors（结构化，不用再自己解析）
```

所有接口共用同一个 JSON 外壳：`{"status", "data", "error", "meta"}`，错误详情用评测组 11 字段标准
（error_id / error_type / severity / code / file / line / module_name / message / column / code_snippet / suggestion）。

**引用方式（过渡期）**：在你的 run_loop.py 头部把 run_sim 目录加进 sys.path：

```python
RUN_SIM_DIR = r"D:\Users\xiaoyaohu\Desktop\项目\ai-agent\run_sim\api"   # 按实际路径改（v2 起接口模块在 api/ 子目录）

```

## 1. 接口一：Lint 检查（lint.py）

### 调用方式

```python
from lint import lint

result = lint(
    source="tools/gen/counter_try1.v",       # 主检查文件（.v/.sv）
    extra_files=["rtl/uart/uart_rx.v"],      # 依赖文件（如 uart_top 需要 rx/tx），没有传 None
    top=None,                                # 顶层模块名，多顶层时指定
    skip_rules=["DECLFILENAME"],             # 屏蔽规则：你生成文件名带 _tryN 后缀，必须传这个
)
```

命令行等价：`python api/lint.py <file.v> [依赖.v ...] --skip-rule DECLFILENAME --top xxx`（在 run_sim 目录下执行）

### 返回 JSON

```json
{
  "status": "fail",
  "data": {
    "source_file": "counter_try1.v 的绝对路径",
    "linter": "verilator(msys2) | verilator(native) | verilator(wsl) | iverilog-fallback",
    "note": "仅降级模式出现：说明当前只有语法级检查",
    "lint_errors": [
      {"line": 15, "column": 5, "rule": "syntax", "severity": "error",
       "file": "counter_try1.v", "message": "英文原始报错",
       "code_snippet": "出错行源码", "suggestion": "中文修改建议"}
    ],
    "metrics": {"latency_ms": 240, "errors": 1, "warnings": 0}
  },
  "error": null,
  "meta": {"timestamp": "...", "version": "1.0", "source_file": "...", "latency_ms": 240}
}
```

### status 语义与退出码

| status | 含义 | 闭环建议动作 | 退出码 |
|---|---|---|---|
| pass | 无任何问题 | 继续仿真 | 0 |
| warn | 只有警告 | 不阻塞，继续仿真，警告留给 RTL 组 | 0 |
| fail | 有错误 | 阻塞 → 回喂/调 auto_fix | 1 |
| unsupported | .vhd 等不支持类型 | 不处理，人工流转 | 2 |

### 你需要改的地方（run_loop.py 的 lint 函数）

你现在的 `lint(v_file, module_name)` 返回 `(bool, msg字符串)`，替换为：

```python
def lint(v_file, module_name=""):
    r = lint_tool(str(v_file), skip_rules=["DECLFILENAME"])
    lint_ok = r["status"] in ("pass", "warn")
    return lint_ok, r
```

- **VERILATOR_BIN / VERILATOR_ROOT / LINT_INCLUDE_DIRS 常量可全部删掉**：探测链已内置
  （Windows PATH → D:\MSYS2\mingw64 等已知路径并自动配 VERILATOR_ROOT → WSL → iverilog 降级）。
  你机器上的 D:\MSYS2\mingw64\bin\verilator_bin.exe 会被自动命中，linter 字段显示 verilator(msys2)。
- 你的 `-y rtl/uart` include 目录需求 → 用 `extra_files=["rtl/uart/uart_rx.v", ...]` 代替。
- **v1.1 起纯警告返回 `warn` 不阻塞**（内部 `-Wno-fatal`）：你的 lint 判定 `status in ("pass","warn")` 写法不用改。
- 多文件联查若互为独立顶层会报 MULTITOP（warn）：有设计层级时传 `top=顶层名` 即可消除。
- 回喂改造：`--feedback parsed` 时不再需要 error_parser.parse()，直接把
  `r["data"]["lint_errors"]`（每条已含 rule/line/message/suggestion）交给你的 feedback_block()；
  字段名对应：code→rule、error_type→severity（语义近似，见下方"待确认"第 2 条）。

## 2. 接口二：仿真一条龙（run_full_flow.py v2.1）

### 调用方式

```python
from run_full_flow import run_full_flow

result = run_full_flow(
    testbench="tb/counter_tb.v",             # 或 make_param_tb 生成的参数化 tb 副本路径
    dut_files=["tools/gen/counter_try1.v"],  # 生成文件 + EXTRA_SIM_RTL 依赖都放这里
    top_name="counter",                      # 顶层名
    sim_timeout=300,                         # 你原来用 300s，默认 60s，记得传
    assert_pass=True,                        # 关键：功能自检，见下
)
sim_pass = (result["status"] == "success")
```

命令行等价：`python api/run_full_flow.py <tb.v> [dut.v ...] --top xxx --sim-timeout 300 --assert-pass`（在 run_sim 目录下执行）

### v2.1 新增：assert_pass（重要）

你 simulate() 里的 PASS 文本判定（tb 打 FAIL 时 vvp 退出码仍是 0，只看返回码会误判通过）
**已原样吸收进工具链**：`assert_pass=True` 时按同一套规则检查 stdout
（有 PASS 且无 FAIL/Error，或正常结束且无 FAIL/Error → 通过）。
不通过时返回 `status=fail` + `error_type=assertion` + `code=RTL-ASSERT-0001`，
message 里带 tb 输出末尾 5 行（可直接用于回喂）。

### 返回 JSON

```json
{
  "status": "success | fail",
  "data": {"output": "仿真stdout", "metrics": {"latency_ms":..., "wave_file": "...", "wave_size_bytes":..., "pass_text_check": true}},
  "error": null 或 11 字段标准错误,
  "meta": {"timestamp": "...", "version": "2.1", "top_name": "...", "testbench": "...", "assert_pass": true, "latency_ms":...}
}
```

失败时 error.error_type ∈ syntax / compile / simulation / assertion / timeout（11 字段，含中文 suggestion）。

### 你需要改的地方（run_loop.py 的 simulate 函数）

```python
def simulate(gen_file, tb_rel, tb_params=None):
    # make_param_tb 参数化逻辑保留（tb 参数改配是你的用例层逻辑，工具链不管）
    ...  # 照旧得到 tb_path 和依赖列表 deps
    r = run_full_flow(str(tb_path), [str(gen_file)] + deps,
                      top_name=module_name, sim_timeout=300, assert_pass=True)
    sim_pass = (r["status"] == "success")
    sim_res  = "PASS" if sim_pass else r["error"]["error_type"].upper()  # 写 run_log
    sim_out  = (r["data"] or {}).get("output", "") or json.dumps(r["error"], ensure_ascii=False)
    return sim_pass, sim_res, sim_out
```

- EXTRA_SIM_RTL（uart_top 挂 rx/tx）→ 填进 dut_files，你的字典照旧，只是传参方式变了。
- 回喂改造：`--feedback parsed` 时 parsed 记录直接取 `r["error"]` 一条即可（已是 11 字段）；
  raw 模式用 `r["error"]["message"]`。

### 行为差异说明（替换前对齐）

| 项 | 你现在 | 工具链 | 说明 |
|---|---|---|---|
| 工作目录 | cwd=rtl1/ | cwd=run_sim/ | tb 里 `$dumpfile("sim/xxx.vcd")` 相对路径会落到 run_sim/sim/ 下；波形检查逻辑兼容，不影响判定，只是落盘位置变 |
| 编译参数 | -g2001 | -Wall（默认标准） | 生成代码是 Verilog-2001，iverilog 默认即支持；-Wall 多开警告不改变通过性 |
| 超时 | 编译- / 仿真 300s | 编译 30 / 仿真 60（可传参） | 传 sim_timeout=300 保持你现有口径 |
| iverilog 版本 | 你机器 0.9.7 | 同一份系统 PATH | 若你版本较老导致 -Wall 行为差异，碰头会现场回归一轮用例确认 |

## 3. 接口三：自动修复（auto_fix.py v1.1，任务三合并完成版）
