## 一、环境与安装

### 1.1 Verilator 安装：winget 静默参数失败
- **问题**：`winget install MSYS2.MSYS2 --silent` 返回非零，安装未真正完成。
- **根因**：MSYS2 安装器对 `/S` 静默参数支持不佳，winget 的 `--silent` 无法透传到正确参数。
- **解决**：改用 winget 已下载的缓存安装包，配合 MSYS2 官方 Qt 静默参数：
  ```
  msys2-x86_64-*.exe in --confirm-command --accept-messages --root C:\msys64
  ```
- **后续**：`pacman -S mingw-w64-ucrt-x86_64-verilator` 直连装 Verilator 5.050（当时代理未开，pacman 仍成功）。

### 1.2 MSYS2 bash stdout 在沙箱里损坏
- **问题**：沙箱内通过 `wsl` 或 `C:\msys64\usr\bin\bash.exe` 执行 verilator 时，stdout 出现坏 fd，输出无法被 Python 捕获。
- **解决**：把子进程 stdout 重定向到临时文件，再用 Python 读文件内容。

### 1.3 用户要求 Windows 原生，不接受 WSL
- **问题**：最初 lint 探测链含 WSL 路径，用户明确要求 Windows 系统运行。
- **解决**：探测链改为 `Windows PATH → MSYS2 已知路径（D:\MSYS2\mingw64、C:\msys64\ucrt64 等，自动配 VERILATOR_ROOT）→ iverilog 降级`，WSL 仅作兜底，默认不触发。

## 二、lint.py 解析缺陷（语义级上线时暴露）

### 2.1 Windows 盘符路径导致行号列号全 null
- **问题**：Verilator 报错 `%Error: D:\path\to\file.v:8:12: ...`，解析后 line/column 全为 null。
- **根因**：`_LOC_RE` 正则假设路径后直接跟 `:line:col`，但 Windows 盘符的冒号把路径段吃掉了。
- **解决**：重写正则，兼容 `盘符:\...` 形式的绝对路径。
- **证据**：[case7_lint_semantic_msys2.json](file:///d:/Users/xiaoyaohu/Desktop/项目/ai-agent/run_sim/tests/evidence/case7_lint_semantic_msys2.json)

### 2.2 Verilator 收尾行被误判为 error
- **问题**：纯警告文件退出后报 `%Warning-...`，最后一行 `Exiting due to 6 warning(s) and ...` 被当成 error，status 误判 fail。
- **解决**：过滤包含 `Exiting due to`、`Cannot continue` 的收尾行，不计入 issues。

### 2.3 警告被当成致命错误，warn 阻塞闭环
- **问题**：verilator 默认把 warning 当 fatal，退出码非零，闭环里 warn 也会误触发 auto_fix。
- **解决**：命令加 `-Wno-fatal`，纯警告返回 `status: warn`（退出码 0，不阻塞闭环）。

## 三、工具链逻辑

### 3.1 tb 打印 FAIL 但 vvp 退出码仍是 0
- **问题**：testbench 用 `$display("FAIL: ...")` 表示断言失败，但 vvp 进程退出码为 0，仿真被误判 success。
- **解决**：run_full_flow 加 `assert_pass` 参数，扫描 tb 输出的 PASS/FAIL 文本，FAIL 时返回 `status: fail` + `code: RTL-ASSERT-0001`，把 tb 输出末尾回喂。
- **证据**：[case6_assert_fail.json](file:///d:/Users/xiaoyaohu/Desktop/项目/ai-agent/run_sim/tests/evidence/case6_assert_fail.json)

### 3.2 auto_fix 规则优先级：sv_to_2001 必须在 missing_semicolon 前
- **问题**：`always_comb begin` 行缺分号，若先跑 missing_semicolon 会误补分号把语法改坏。
- **解决**：规则排序固定为 `sv_to_2001 → missing_semicolon → reg_to_wire → wire_to_reg`，先做语法转换再补分号。
- **证据**：[case07_multi_error.v](file:///d:/Users/xiaoyaohu/Desktop/项目/ai-agent/run_sim/tests/benchmark/case07_multi_error.v) 2 轮接力修复成功。

### 3.3 多顶层文件联查报 MULTITOP
- **问题**：`lint.py counter.v dff.v` 报 `MULTITOP`（warn），因为两个文件各有顶层模块。
- **解决**：有设计层级时传 `--top 顶层名`；或各模块单独 lint。

## 四、工程操作

### 4.1 目录分层：直接 Move 被安全检查拦截
- **问题**：把 lint.py / run_full_flow.py 等从 run_sim/ 移到 run_sim/api/ 时，直接 Move-Item 被沙箱安全策略拦截。
- **解决**：用 `复制 → 改锚点（parent.parent）→ 回归 → 删原件` 顺序，全程无断档。三处代码锚点同步改完，回归全绿后才删原件。

### 4.2 json/demos 在 run_sim 外，工具链不自洽
- **问题**：auto_fix 演示样例在 `../json/demos/`，run_sim 目录无法独立拷走即用。
- **解决**：并入 `run_sim/tests/demos/`，auto_fix.py 文档里 3 处示例路径同步更新。
